# ADS v0.4.2

Maintenance security-boundary contract update from immutable ADS v0.4.1. This release is **NOT proof of macOS filesystem sandbox enforcement**. Consumers must update their pinned `.ads` Git Submodule only through an approved, reviewed change; no Consumer project or host configuration changes automatically.

## Security and behavior

- Default project-scoped read **and** write authorization for the main TUI Agent, subagents, shell, Python, Read/Glob/Grep, CodeGraph/RTK indexers and connected filesystem MCPs. Project-only rules now expressly prohibit unauthorized listing, searching, hashing or reading of out-of-project personal files such as `~/Music` and other sibling/home directories.
- Add `docs/host-filesystem-boundary.md`: host-version-specific preflight, approved workspace roots, synthetic test protocol, deny-by-default external paths, per-tool and per-child proof, separation of prompt guidance from actual OS enforcement.
- Add opt-in Codex filesystem-permission-profile template `templates/host-access/codex-workspace-only.toml`. A supported Host version must apply it explicitly; do not mix permission profiles with legacy sandbox flags.
- Add `scripts/host_filesystem_probe.py` with hermetic negative-test coverage. It reports whether synthetic outside reads/listings/hash/symlink attempts were blocked, without dumping contents. This script **tests** the host's permissions; it does not sandbox a process.
- Update SAFETY.md, STANDARD.md, the README entrypoint and Bootstrap/Adopt/Deliver Skills for the project-only read preflight.
- Preserve v0.4.1 Git governance, Consumer CodeGraph/RTK toolchain and production-boundary contracts. CNB opt-in variant remains independently developed under Issue #63.

## Known limitations

- **macOS main TUI project-only read isolation: NOT_VERIFIED.** User reported project-external directory exploration. GitHub tests verify the normative rule and synthetic test instrument, NOT real enforcement in the user's Mac TUI. Host-level live negative testing with harmless fixtures is still required before Issue #72 may be closed.
- A Codex legacy `workspace-write` sandbox is not enough to establish read-only confinement. Codex Permission Profiles vary by supported CLI version, configured scope and active runtime. Claude Code/OpenCode and MCP/native tools need separate effective-permission proofs.
- The per-host verification must cover parent Agent, children, filesystem/search tools, shell, symlink escapes and connected MCP, using actual synthetic positive and negative controls. Do not infer PASS from an empty Git patch or lack of visible exfiltration.
- CNB full integration, billing/quota behavior, Native NPC and dual-platform release pilots remain separately unverified work tracked by Issue #63. They are not silently promoted by v0.4.2.
- ADS private repository branch-protection may be restricted by plan; a green CI run alone does not establish server-side protection.
