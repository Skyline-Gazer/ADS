# ADS v0.4.2 release safety contract

Issue #72 describes a local macOS TUI reading or exploring user directories outside an authorized project. The source fix merged into dev in PR #73, but OS-level host confinement remains NOT_VERIFIED.

This release publishes improved normative Consumer rules, a version-gated opt-in permission-profile sample and an entirely synthetic regression probe. **It does not claim a universal OS sandbox or real user-machine containment.**

Publication process follows v0.4.1: preserve existing `main` ancestry, build a reviewed candidate on `dev`, run all four exact-SHA ADS CI workflows and an independently verified pinned private Consumer Sandbox. Then create the sole release authorization manifest (`release/v0.4.2-publish.json`) on a separate `release/*` PR to `main` bound to the exact candidate and previous main SHA. The publisher only fires on the authorized manifest main push, revalidates all evidence, and creates an immutable annotated tag and GitHub Release. Never overwrite previous releases; no production Consumer deployment is authorized.

Do not close Issue #72 until independent macOS TUI denial has been proved through the actual native tool and MCP routes.
