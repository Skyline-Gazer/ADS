# ADS v0.4.1

Maintenance stabilization after immutable v0.4 (`2af17d9e1d816844c49835ae91b784405765ad46`). Consumer repositories must explicitly update their pinned `.ads` Submodule through a reviewed PR; ADS does not update consumers automatically.

## Fixes and tested improvements

- Correct development version-header drift without rewriting v0.4 history.
- Make mandatory consumer tool initialization executable: check official channels and versioned license/provenance evidence against active executable paths and hashes, initialize only absent project integration, verify current-worktree JSON status and real source queries, and permit bounded recovery only for observed unhealthy indexes.
- Use an explicit project-local Codex RTK adapter, verify Full Edition evidence, representative compression, and failure exit-code/diagnostic preservation. Block missing tools, wrong editions, unauthorized updates, ambiguous provenance and escaping project paths.
- Keep native Agent Host MCP/hook verification separate from CLI/project checks. Exit 3 is CLI success with Host verification pending, never a complete adoption PASS.
- Preserve development configuration continuously on dev and strip it only on independent release-preparation branches. Check production trees and actual extracted build outputs, including dependency directories and custom paths retained through an external trusted manifest.
- Exercise real local Git Submodule v0.4 → candidate → v0.4 upgrade/rollback, real official tools in disposable Linux consumers, and a separate trusted private Submodule sandbox receipt.
- Add v0.4.1-specific publication validation, immutable annotated tags, exact-target CI/consumer receipts, preserved main ancestry and idempotent recovery after a tag-only partial publication. Older release workflows and audit records remain intact.

## Compatibility and experimental scope

GitHub Primary and the Issue → task branch → PR to dev → separate production release PR model remain the default. Existing CNB Primary + GitHub Mirror, current-source-SHA review, bounded Agent fixes and one-way approved main/tag synchronization remain opt-in experimental templates; regression tests do not establish a live cross-provider pilot.

CNB Development + GitHub Release Gate is an unsupported, default-off proposal. Its lifecycle now preserves developer configuration on dev; new adapters, real CNB/Greptile review, native protection and production cutover are deferred. Unknown provider modes remain rejected. No new paid service, credential scope, global tool installation or provider migration is required by this release.

## Known limitations

- Isolated Linux CLI and MCP stdio tests cannot verify the user's native Agent Host MCP routing or RTK interception. Consumers must record those smoke tests separately; unsupported project host adapters remain explicit limitations.
- Official CodeGraph stable distribution may be unavailable. Only verified official-channel absence and an explicitly reviewed immutable official source pin permit SOURCE_FALLBACK; it is not a stable release and never silently follows upstream HEAD. RTK stable releases are observed dynamically.
- Full RTK includes Apache-2.0 and BUSL-1.1 components. Installation/license evidence is an explicit provenance attestation, not a proof of all downstream rights or binary reproducibility. Reassess changed grants before tool upgrades.
- ADS private-repository branch protection/Rulesets inspection may return a GitHub-plan restriction. CI and PR evidence do not establish unavailable server-side enforcement.
- CNB/NPC/Greptile live pilot and provider cutover remain unverified follow-up under Issue #63. Historical host acceptance records retain their original failures and scope.

Release readiness, exact target, CI URLs, independent consumer receipt and the final Owner authorization are recorded separately in the v0.4.1 readiness report. ALNILAM product/Shirone failures are outside this maintenance release's gates.
