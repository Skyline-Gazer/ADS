# ADS v0.4 — release readiness

**State: NO-GO / NOT RELEASED (2026-10-25).** This is an evidence-based release decision, not a release announcement. The latest published ADS tag and GitHub Release remain **v0.3**.

## Candidate scope

- Consumer projects adopting ADS must use the latest stable **CodeGraph** and **full RTK** during development, with consent-gated installation, exact source/edition provenance, working host integration, fresh CodeGraph indexes, and dev-only configuration.
- Mandatory Git flow: task branches from `dev`, Issue/PR, CI, separate reviewed `dev`→`main` promotion, server-side protection only where the GitHub plan actually supports it.
- ADS itself has an MIT license; its consumers retain independent code licenses. CodeGraph is MIT; full RTK currently contains Apache-2.0 CLI/filters and BUSL-1.1 engine with an Additional Use Grant. Actual version-specific license/grant provenance and usage classification are required.
- Do not embed developer tool integration/configuration or generated CodeGraph databases and binaries in an adopting project's production `main`.

## Current blocker

Official upstream [CodeGraph](https://github.com/andysom25/codegraph) documents both `@andysom25/codegraph` npm installation and GitHub Releases standalone downloads, but the live GitHub Actions installation test returned `E404` from npm. Independently the official GitHub Releases collection returned an empty list and `releases/latest` returned 404. Neither historical pinned-version guesses nor replacing full RTK with `rtk-oss` meets the mandatory ADS policy.

The failure occurred *before* the real consumer pilot could index sources or test the RTK host integration. It cannot count as a PASS. Do not weaken or disable required checks to achieve publication.

## Publication procedure after recovery

1. Recover an official, installable stable CodeGraph distribution; update the preflight/checks to reject unavailable latest-stable metadata instead of asserting freshness, and pass the bounded pilot in KIRARI and AiringCal at the exact ADS candidate SHA.
2. Review MIT/Apache-2.0/BUSL-1.1 actual distributed license files, evidence hashes, edition/usage constraints, source drift, and branch-boundary oracles; reconcile #45/#51/#53.
3. Pass `Validate ADS`, isolated consumer compatibility and real private pinned-submodule acceptance on the immutable reviewed release candidate (or clearly document any gate requiring the owner's new scope decision).
4. Open a **separate release PR from `dev` to `main`**, review its complete diff and exact Actions results, and merge only after successful verification. Direct writes to `main` are prohibited.
5. Publish a new, annotated `v0.4` tag and GitHub Release on the verified commit without replacing an existing tag. Re-fetch GitHub's published release and tag/ref; record the exact target SHA and CI receipt.
6. Only after publication, update the version status and close verified release Issues. Consumer projects remain independently opt-in; publishing ADS does not automatically update or deploy them.
