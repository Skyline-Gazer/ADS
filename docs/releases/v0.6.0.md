# ADS v0.6.0 — Adaptive Goal Execution

**Status:** in development on `dev`. Not a published tag. Baseline: published [v0.5.0 Lite](https://github.com/Skyline-Gazer/ADS/releases/tag/v0.5.0) (`9bd8b11`).

**Design constraint:** v0.6 is an **execution-semantics patch**, not a second standards inflation.

**Principle:** 目标不漂移、安全不退让、路径可调整、结果必须验证、任务必须收敛。

## Tracking Issue (Owner action)

Agent `POST /repos/Skyline-Gazer/ADS/issues` returns **HTTP 403** (`Resource not accessible by integration`). Owner: create one GitHub Issue titled `ADS v0.6.0 — Adaptive Goal Execution` using the Goal / Non-goals / Acceptance sections below, then update the implementation PR to `Refs #<n>` (or `Closes #<n>` when acceptance is fully proved). Until that Issue exists, PRs may temporarily `Refs` an existing resolvable Issue solely for git-governance syntax.

## Goal

Let agents pursue an authorized Goal across hosts and environments by adapting path when needed, while keeping invariants, proving outcomes with real state, and converging the task inside existing authorization.

## Non-goals

- No new orchestrator, task database, CLI, or second tracker
- No restoring Mode B
- No re-mandatory Strict Git / CodeGraph / Strict Lifecycle
- No Recipe that copies [cnb-review.md](../cnb-review.md) or other existing Provider docs
- No automatic Tag/Release in the first implementation PR
- No claim that every Agent Host has verified OS isolation

## Core changes (P0)

| Change | Where |
| --- | --- |
| Goal Contract (session-local) | `skills/deliver`, brief `STANDARD` |
| Adaptive Strategy | `skills/deliver`, `skills/recover` |
| Outcome Verification (Process / State / Outcome) | `QUALITY`, `skills/deliver` |
| Convergence within authorization | `skills/deliver`, `skills/recover` |

Recipes: add **only** when an existing doc cannot guide execution. None required to ship P0 if Skills + QUALITY suffice.

## Acceptance — six counterexamples

| ID | Scenario | Expected |
| --- | --- | --- |
| A01 | Stale harness demands restoring deprecated capability | Keep Goal; fix fixture; do not revive abandoned contract |
| A02 | Unfinished PR already exists for same Goal | Take over; do not open a parallel chain |
| A03 | Review PASS with open material comments | Do not merge ([cnb-review.md](../cnb-review.md) when CNB) |
| A04 | Mid-run / partial failure | Re-read actual state before repair |
| A05 | Project-outside read/write without grant | Enforced deny, or `BLOCKED` / `NOT_VERIFIED` — never “safe because Markdown said so” |
| A06 | GitHub vs CNB different mechanics | Same delivery Goal; no duplicate Provider orchestration |

## Acceptance — v0.5.0 Lite regression

Ordinary development must **not** regain: mandatory execution framework, mandatory consumer toolchain, second task system, or extra mandatory ceremony beyond a short Goal Contract when useful.

Evidence: [scenarios/v0.6-adaptive-goal-execution.md](../../scenarios/v0.6-adaptive-goal-execution.md).

## Publication

Tag/Release is a **later Owner decision** after evidence review. First ship is a PR to `dev`, then optional sync into `cnb/dev` without force-overwrite.
