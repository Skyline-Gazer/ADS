# ADS v0.5.0 Lite — release safety contract

**Status:** release-transport candidate. Merging this contract and the Lite tree to `main` does **not** by itself create the annotated `v0.5.0` tag or GitHub Release.

## Intent

Publish a single consumer pin `v0.5.0` that defaults to [lite adoption](../lite-adoption.md): submodule + short root `AGENTS.md` + core rules. Strict Git, CodeGraph/RTK, and Strict Lifecycle remain **optional profiles**. CNB Primary remains Mode A (exact-SHA mirror); Mode B stays cancelled. No `v0.5.0-cnb` tag.

## Publication gate (still required for the annotated tag)

Follow the same class of controls as v0.4.2:

1. Exact-SHA ADS CI on the frozen release target (four workflows).
2. Independently verified private Consumer Submodule acceptance against that exact SHA.
3. Separate Owner `release_approved` manifest on `main` (`release/v0.5.0-publish.json`) bound to previous `main` SHA.
4. Publisher creates immutable annotated tag + GitHub Release only after revalidation.

Until those complete, consumers may review the `main` tip after this PR merges, but must **not** treat an untagged `main` tip as the official `v0.5.0` pin unless the Owner explicitly authorizes SHA pinning.

## Explicit non-claims

- Sync-branch GitHub PR merge ≠ Mode A exact-SHA mirror PASS ([cnb-sync.md](../cnb-sync.md)).
- macOS TUI project-only read isolation remains **NOT_VERIFIED** where previously documented.
- This release does not deploy consumer production software.
