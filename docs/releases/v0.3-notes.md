# ADS v0.3

**Stable core release.** ADS is a host-neutral, agent-native development standard for AI-assisted software projects. It prioritizes scoped authorization, independent verification, remote-first CI and preview environments, and small, reviewable changes over mandatory local infrastructure.

## Included

- Goal-driven continuous implementation with proportional planning, parent-owned integration and explicit delivery evidence.
- Remote-first verification: reuse GitHub Actions and platform previews; create only minimal, task-scoped remote environments when needed; keep local setup as a lightweight fallback.
- GitHub Project milestone reconciliation at meaningful phase boundaries, with drift detection and evidence-backed repair.
- Git Submodule-based adoption and updates pinned to immutable SHAs, with a documented review, upgrade, consumer-CI and rollback lifecycle.
- Optional host-native Multi-Agent delegation with explicit safety constraints, serial fallback and independent correctness checks.
- Host-neutral policy, Skill discovery, security boundaries, and honest distinctions between CI, sandbox, external integration and production verification.

## Verified release gates

- ADS tests and policy/documentation/Skill checks passed on the frozen release target.
- GitHub-hosted KIRARI and AiringCal isolated compatibility workflows passed against immutable consumer source SHAs, including candidate upgrade and rollback without modifying those consumer repositories.
- The private ADS Submodule acceptance workflow recursively checked out the exact private ADS gitlink, verified the parent pin equals the nested checkout and expected SHA, verified required policy and Skill paths, and passed the consumer contract tests.
- The release workflow checks the exact frozen target's CI receipts and the actual private workflow run before creating the annotated tag and GitHub Release.

## Known limitations

- Multi-Agent is optional and host/task dependent. Small N=1 pilot observations were generally slower in parallel mode; ADS makes no generic speedup, model-winner or billed-cost claim.
- Historical authorization failures and unattributed configuration writers remain preserved in the acceptance record. Later bounded sandbox verification does not erase earlier failures.
- Default OMP/OpenCode subagents have demonstrated permission-inheritance and filesystem-containment hazards in tested configurations. Sensitive work must use task-specific proven containment, a safe serial/read-only path, or abstain.
- Not every host, model, OS, production integration, or remote platform is universally certified. Consumer projects must run their own checks.

## Adoption

Pin the released immutable commit as a Git Submodule and review updates in a consumer PR. Do not track ADS `main` implicitly. Follow [the update guide](https://github.com/Skyline-Gazer/ADS/blob/v0.3/docs/how-to-update.md).
