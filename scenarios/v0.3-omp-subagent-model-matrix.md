### What the numbers say

- Children are **not** free: each one re-prefills the entire harness system prompt. Under model A the two children started with 16,000 cached tokens already, so their first request cost 1,193–1,218 fresh tokens; under model B nothing was cached and each child paid **17,243–17,294 fresh input tokens** before doing any work.
- Total usage grew **2.83×** (A) and **4.43×** (B) versus the serial baseline, while wall time grew **1.82×** and **3.47×**. On this workload and N=1, delegation did not repay its startup cost.
- The serial baseline is not slow: it read the same contract, wrote both modules and ran the suite in ~24 s under both models. Nothing about the medium task forces concurrency.
- Host-estimated spend for the four comparison cells is **USD 0.0720**; including the failed first attempt and both authorization probes it is **USD 0.1241**. Actual billing is **NOT OBSERVED**: the account is a routing group and the host figure is a catalog estimate, not an invoice.

## Preserved failures and deviations

These are kept rather than smoothed over. Only one cell was rerun, and only after a harness defect was found and the fix applied identically to both models.

1. **`A-multi` first attempt — FAIL, discarded from comparison.** The parent spawned both children and then ended its turn; in print mode that disposes the children before they do work. Both child sessions exist and exit at the same millisecond, `git status` stayed clean, and the run took 15.167 s with zero application progress. The scheduler rule was then made explicit ("do not end your turn before both children settle") and `wait` was added to the tool list for both models. The failed cell is archived as `cells/A-multi-early-exit`.
2. **Per-call worker model — NOT SUPPORTED.** Passing `model` on a batch item is rejected at validation with `model is only accepted for the seance agent.` Model choice for a worker therefore lives in agent frontmatter, `task.agentModelOverrides` or a role mapping, none of which the parent can vary per item at call time.
3. **Isolation is a workspace, not a boundary — FAIL for absolute paths.** With `isolated: true`, each child did get its own checkout under `~/.omp/wt/<id>/m`, and each received its own patch file. A direct probe then had two isolated children append to one absolute path outside both worktrees: both succeeded, the file retained both marker lines, and both patch files were 0 bytes. In `B-multi` the same mechanism occurred unintentionally: the parent's task text named the parent worktree path, and both children wrote `/…/cells/B-multi/app/*.py` directly, bypassing their own checkouts. `A-multi2` shows the intended path: the children wrote inside their own trees and the parent applied non-empty patches.
4. **Oracle deviation, preserved.** My independent oracle initially included a conversion of `10**400`. The contract does not specify huge integers, so the check was withdrawn. Before withdrawal all four cells failed it differently: `A-serial` raised `ValueError`, the other three leaked `OverflowError`. The oracle's label for that check (`FAIL: no ValueError`) was also misleading. The final 17 checks avoid out-of-contract input; this deviation is not used as a cell verdict.
5. **Second model availability, probed not assumed.** `magpie/openrouter/openai/gpt-6.1-sol` returned `402 OpenRouter: Insufficient credits`; `magpie/group/grok` aborted after the 60 s probe budget; `magpie/qoder-cn/kmodel_latest` returned a provider `400`. `deepseek/deepseek-v4-flash` and `deepseek/deepseek-v4-pro` both answered a tool-free probe and were used. Both are one provider at one price, which is recorded as a comparability limit.

## NOT TESTED

- Repetitions, alternation and medians (Stage 2); the protocol asks for three fresh runs per mode before selecting a default.
- Tiny and coupled workloads; only the medium independent task was run.
- A third model, a different provider, or the strong-parent/cheap-worker variant.
- Cross-host comparison; no second host ran this fixture in this session.
- Hostile-child authorization cases where the child is granted a narrow scope and then tries to widen it, and worker-failure recovery.
- Network-touching tasks; tool network use was never requested.

## Decision

For this host and workload: prefer serial. Serial completed the medium task in roughly half (A) to a third (B) of the multi wall time with 2.8–4.4× fewer tokens, and the first multi attempt produced no application work at all until the harness explicitly required the parent to wait for its children. Native children are genuinely available and genuinely concurrent, so Multi-Agent remains a defensible choice when each subtask is large enough to absorb a full system-prompt prefill and the parent has independent work meanwhile — neither held here.

Two operational rules follow from the failures, and both are host behaviour rather than model behaviour: keep the parent alive until children settle, and treat `isolated: true` as working-directory plumbing, not containment. A child that is given an absolute path outside its worktree can write there, so file ownership must be enforced by instruction and checked by the parent's diff review, or by an OS-level sandbox this experiment did not configure.

No ADS guidance, Skill or template was changed to encode these numbers. They are one host, one task and N=1.
