# Working on ADS itself

ADS is a lightweight standard, not a new execution framework. Read README.md, STANDARD.md, SAFETY.md and QUALITY.md before structural changes. Keep capabilities agent-native: SKILL.md files, concise templates and optional profiles. Do not add a CLI, runner, state machine, duplicate tracker or deployment system unless separately authorized. Preserve project-local limits. Prefer remote CI and target-platform previews when relevant; if absent, autonomously provision a minimal task-scoped remote environment within existing authorization, credentials, permissions, quotas and budget. Ask the user only for the exact missing owner action when a real boundary is reached, and continue independent safe work. Keep local validation lightweight; do not create long-lived infrastructure or incur new recurring spend outside scope. For edits verify Markdown links, relative paths, frontmatter and realistic task instructions. Keep changes scoped, commit on a task branch and summarize what was and was not verified. ADS itself must follow [docs/git-governance.md](docs/git-governance.md): start ordinary task branches from the latest `dev`, reference an Issue, open a PR to `dev`, and never push task commits directly to `dev` or `main`. Treat `main` promotion as a separate release PR.
